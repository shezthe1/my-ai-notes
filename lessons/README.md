# 차시 제작 규격 (듣기 · 활동 4개형)

듣기06 「선생님의 안내를 듣고 준비해요」를 기준으로 만든 제작 규격입니다.
차시 내용은 **명세 파일(JSON)** 에만 쓰고, 화면·디자인·동작은 **공통 템플릿**이 맡습니다.
새 차시는 명세 파일 하나를 만들어 빌드하면 됩니다.

## 기준 브라우저: 크롬

PC·태블릿·휴대폰 모두 **크롬**을 기준으로 만들고 검사한다.

| 환경 | 처리 |
|---|---|
| PC 크롬 | 마우스로 끌어 놓기 |
| 태블릿·휴대폰 크롬 | 손가락으로 끌어 놓기, 또는 카드를 누른 뒤 칸을 눌러 놓기 |
| 화면 크기 | 1600×900 화면을 기기 화면에 맞춰 확대·축소(가운데 정렬) |
| 휴대폰 세로 | '화면을 가로로 돌려 주세요' 안내 표시 |

- 아이폰·아이패드의 크롬은 애플 정책상 사파리와 같은 엔진(WebKit)으로 동작한다. 안드로이드·PC 크롬과 다를 수 있어 따로 확인이 필요하다.

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `engine.html` | 공통 템플릿(도입 → 목표 → 활동 안내 → 활동 1~4 → 마무리, 1600×900) |
| `specs/*.json` | 차시 명세. 파일 이름 = 차시 ID(커리큘럼 엑셀과 같음) |
| `assets/objects/` | 사물 이미지(800×600, 투명 배경, 면적 기준 크기 통일) + `index.json`(낱말 → 파일) |
| `assets/characters/` | 캐릭터 이미지 + `index.json`(이름 → 파일) |
| `build.py` | 명세 → 단일 HTML(이미지·QR 생성기 포함) |
| `assets/vendor/qrcode.js` | QR 코드 생성(MIT, Kazuhiko Arase). 표지의 학생에게 보내기에 씀 |
| `test_lesson.js` | 자동 검사, PC 크롬(화면 8개, 음성, 활동2·4 오답/정답, 예시 화면) |
| `test_touch.js` | 자동 검사, 태블릿 크롬 터치(손가락 끌기, 눌러서 놓기, 터치 선택) |
| `test_acts.js` | 자동 검사, 활동 종류별(문제 풀이·녹음(가짜 마이크)·짝 잇기·따라 쓰기·순서 놓기·카드) |
| `out/` | 완성 파일 |
| `tools/` | 새 사물 이미지(책·자·도화지) 렌더·규격화 스크립트 |
| `prototypes/말하기_녹음_시험.html` | 말하기용 녹음·다시 듣기 시험 페이지 |

## 만드는 순서

1. `specs/`의 기존 명세를 복사해 새 차시 ID로 이름을 바꾼다.
2. `meta`(진단 코드·진단 발문·변형 내역)와 활동 내용을 고친다.
3. 필요한 사물 이미지가 없으면 `assets/objects/`에 같은 규격으로 넣고 `index.json`에 낱말을 등록한다.
4. 빌드: `python3 build.py specs/차시ID.json out/차시ID.html`
5. 검사: `node test_acts.js "$PWD/out/차시ID.html" 스크린샷폴더` → `ALL PASS` 확인. 듣기06처럼 예시·순서 놓기를 쓰는 차시는 `test_lesson.js`·`test_touch.js`도 돌린다.
6. 실제 기기에서 소리를 들어 보고 숫자·낱말 발음을 확인한다.

## 명세 항목

| 항목 | 설명 |
|---|---|
| `meta.id` `grade` `area` `level` `std` | 차시 ID와 학년군·영역·수준·성취수준 번호 |
| `meta.std_text` `codes` | 성취수준 원문, 연계 진단 문항 코드 |
| `meta.diag_prompt` | 진단 원고의 발문(같은 문장을 쓰지 않았는지 빌드에서 검사) |
| `meta.variation` | 원고 → 콘텐츠로 바꾼 내역 |
| `meta.basis` | 제작 근거·확인할 점 |
| `book` `unit` `title` | 상단 표시(교재명 · 단원 · 차시명) |
| `cover` | 칠판 제목(HTML), 설명 문장(읽어 주기), 캐릭터 2명 |
| `goal` | 학습 목표 문장(읽기용 `text`, 화면용 `html`), 캐릭터 |
| `guide` | 활동 안내 카드 4장(제목·설명·캐릭터) |
| `files` | 표지의 한글 파일 목록(`label`, `file`: hwp·hwpx 경로) |
| `acts` | 활동 1~4. 활동마다 `type`·`title`·`ins`와 종류별 항목(아래 표) |
| `end` | 마무리 제목·문장·배너·캐릭터 |
| `feedbackChars` | 정답·오답 팝업 캐릭터 |

## 활동 종류 (`acts[].type`)

낱말이 이미지 라이브러리에 있으면 그림 카드, 없으면 글자 카드로 나온다(바, 사처럼).

| 종류 | 화면 | 명세 항목 |
|---|---|---|
| `cards` | 카드를 눌러 소리 듣기 | `items`(4·6개) |
| `choose` | 안내를 듣고 여러 개 골라 확인 | `say`, `options`(5), `answer`, `ok`, `bad` |
| `example` | 안내를 듣고 예시 화면 보기 | `say`, `question`, `example` |
| `order` | 들은 순서대로 끌어 놓기 | `say`, `cards`(`icon` 또는 `img`), `answer`, `ok`, `bad` |
| `quiz` | 여러 문제를 차례로. 정답 하나면 누르는 즉시, 둘 이상이면 골라서 확인 | `rounds`[`say`, `options`, `answer`], `ok`, `bad` |
| `record` | 녹음 → 내 목소리 듣기. `mode`: `repeat` 듣고 따라 말하기 · `name` 그림 보고 말하기(녹음 뒤 정답) · `qa` 묻는 말에 대답(`ask`) · `read` 소리 내어 읽기 · `review` 비교하고 스스로 평가 | `mode`, `items`, (`ask`) |
| `match` | 낱말과 그림을 눌러 잇기, 틀린 줄만 지움 | `pairs`[`word`, `img`], `right`(그림 순서, 섞어서), `ok`, `bad` |
| `trace` | 손가락·마우스로 쓰기. `mode`: `trace` 흐린 글자 따라 쓰기(덮은 비율 50% 이상, 바깥 35% 이하) · `free` 혼자 쓰고 바른 글자와 겹쳐 비교 | `mode`, `items`, `ok` |

녹음은 같은 낱말이면 활동이 바뀌어도 다시 들을 수 있고(화면 메모리), 발음은 자동 채점하지 않는다.
따라 쓰기 판정은 흐린 글자를 덮었는지만 보며 글씨를 바르게 썼는지는 판단하지 않는다.

## 표지 도구

- **한글 파일**: `files`에 적은 hwp 파일을 내려받는다. 파일 자체(활동지·지도 자료)는 원고에서 따로 만들어 같은 경로에 둔다.
- **학생에게 보내기**: 지금 수업 주소를 QR 코드와 링크로 보여 주고 링크를 복사한다. 내 컴퓨터에서 연 파일(file://)이면 학생 기기에서 열리지 않는다는 안내를 함께 띄운다.

## 빌드에서 자동으로 막는 것

- 이미지 라이브러리에 없는 낱말·캐릭터
- 정답이 보기에 없거나, 순서 정답과 카드가 맞지 않음
- 개수 규격 위반(안내 카드 4, 활동 4. 예전 형식 a1~a4는 낱말 카드 6, 보기 5)
- 문제·짝 잇기의 정답이 보기에 없음, 짝 잇기 그림이 낱말과 같은 순서, 녹음·쓰기 방식 이름 오류
- 한글 파일이 아닌 파일을 `files`에 적음
- 읽기 문장에 숫자가 있음 → 읽는 말로 풀어 쓴다(예: `10쪽` → `십 쪽`, `8쪽` → `팔 쪽`)
- **진단 원고의 발문을 그대로 사용함**

## 디자인 테마

`engine.html`의 「테마: 플랫 + 종이 오림, 연한 파랑 바탕」 구역에서 정한다.

| 대상 | 규칙 |
|---|---|
| 바탕 | 연한 파랑(`--paper` #eef4fa). 도입·마무리는 종이 물결 겹(톤온톤) |
| 탭·박스·버튼·팝업 | 플랫: 그림자·그라데이션 없이 단색과 테두리. 버튼만 아래 받침선 |
| 도입·마무리 장식 | 칠판·말풍선·글자 블록·공책·도장을 오린 종이를 겹친 모양으로 |
| 사물 실사 이미지·캐릭터 | 바꾸지 않는다 |

- 떠 있는 자음·모음 장식과 ㄱ·ㄴ·ㄷ 타일은 쓰지 않는다.
- 글자 블록은 읽는 순서대로 놓는다(마무리 '한국어'는 한 줄, `blocks row`).

## 원고 변형 원칙

학습 콘텐츠는 진단 문항과 같은 형태로 만들되, **소재와 상황은 살짝 바꾼다.**
진단 문장을 그대로 학습하면 재진단의 의미가 약해지기 때문이다.

| 진단 원고 | 콘텐츠 |
|---|---|
| 교과서 10쪽을 펴세요. | 교과서 8쪽을 펴세요. |
| 포도, 사과, 우유 | 딸기, 바나나, 사과 |
| 어머니께 인사를 합니다. | 할머니께 인사를 합니다. |
| 준비물(자, 도화지)를 꺼내세요. | 풀과 도화지를 꺼내세요. |
| 줄을 그으세요. | 자로 선을 그으세요. |

## 말하기 녹음 (검증 결과)

브라우저 기본 기능(`getUserMedia` + `MediaRecorder`)만으로 녹음 → 바로 다시 듣기가 가능하다. 서버·저장 없음.
녹음은 그 화면의 메모리에만 있고, 화면을 닫으면 사라진다.

| 조건 | 결과(Chromium, 가상 마이크) |
|---|---|
| 파일을 바로 열기(`file://`) | 녹음·재생 됨 |
| https 사이트 | 녹음·재생 됨 |
| 다른 사이트에 iframe으로 넣음, `allow="microphone"` 없음 | 막힘(NotAllowedError) |
| iframe에 `allow="microphone"` 있음 | 녹음·재생 됨 |
| 마이크 없음 | 안내 문구 표시(NotFoundError) |
| **Windows 크롬 실제 기기** | **녹음·다시 듣기 확인됨(사용자 확인)** |

- 처음 한 번 브라우저의 마이크 허용 창이 뜬다.
- http(보안 연결 아님) 사이트에서는 막힌다.
- 기준 브라우저는 크롬. 아이폰·아이패드 크롬(WebKit)은 시험하지 못했으므로 쓸 경우 실제 기기 확인이 필요하다.
